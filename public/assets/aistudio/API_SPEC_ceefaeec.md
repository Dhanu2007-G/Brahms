# AstraPulse — REST API Specification (v1)

Base path: `/api/v1` · Format: JSON (`application/json`) · Errors: `application/problem+json` (RFC 7807)
OpenAPI is auto-generated by FastAPI at `/docs` and `/openapi.json`; this file is the human-readable contract.

---

## 1. Conventions

| Topic | Rule |
|---|---|
| Auth | `Authorization: Bearer <access_token>`; refresh via httpOnly cookie |
| Time | ISO-8601 UTC (`2026-11-14T05:30:00Z`) |
| IDs | UUIDs |
| Pagination | `?limit=50&cursor=<opaque>`; response `{items, next_cursor}` |
| Idempotency | `Idempotency-Key: <uuid>` on mutating endpoints; replay returns original response (`200`) |
| Rate limits | Auth endpoints: 5/min/IP + back-off; others: 120/min/user |
| Missing values | JSON `null` — never `0` |
| Provenance | Every health value in a response includes `data_source` and `observed_at` |

**Error body**
```json
{
  "type": "https://astrapulse.dev/problems/validation-error",
  "title": "Validation failed",
  "status": 422,
  "detail": "One or more fields are invalid.",
  "instance": "/api/v1/checkins",
  "errors": [{"field": "observations[0].value", "message": "Outside plausible range 20–250 bpm"}]
}
```

**Status codes:** 200, 201, 204, 400, 401, 403, 404, 409, 422, 429, 500, 503.

## 2. Endpoints

### 2.2 Auth
| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/auth/login` | none | Email + password → access token; sets refresh cookie |
| POST | `/auth/refresh` | cookie | Rotate refresh, new access token |
| POST | `/auth/logout` | user | Revoke refresh token |
| GET | `/auth/me` | user | Current user + role |

**POST `/auth/login`**
```json
// request
{"email": "astra001@ares01.demo", "password": "••••••••"}
// response 200
{"access_token": "…", "token_type": "bearer", "expires_in": 900, "role": "astronaut"}
```

### 2.11 Sync
| Method | Path | Description |
|---|---|---|
| POST | `/sync` | Batch of pending items from the client outbox |

```json
// request
{"items": [
  {"type": "checkin", "client_id": "…", "payload": { /* same as POST /checkins */ }},
  {"type": "journal", "client_id": "…", "payload": { /* journal create */ }}
]}
// response 200
{"results": [
  {"client_id": "…", "result": "accepted", "server_id": "…"},
  {"client_id": "…", "result": "duplicate", "server_id": "…"},
  {"client_id": "…", "result": "rejected", "reason": "Outside plausible range", "field": "…"}
]}
```
Per-item results; one bad item never fails the batch. Items are processed in submitted order.

## 3. Authorisation summary

| Endpoint group | Astronaut | Specialist | Admin |
|---|---|---|---|
| Own check-ins/observations | ✅ | ❌ | ❌ |
| Granted crew data | ❌ | ✅ (scoped) | ✅ (audit) |
| Alerts review | ✅ own | comment only | read |
| Journal | ✅ own | shared only | ❌ |
| Grants | ✅ manage own | request | manage |
| Seed/audit/rulesets | ❌ | ❌ | ✅ |

Every cross-user read writes an `audit_logs` row.

## 4. Contract tests (must exist)
- Unauthenticated → 401 on every non-public route.
- Wrong role → 403; other user's resource → 403 or 404 (no existence leak).
- Replaying the same `Idempotency-Key` returns the same body, no new rows.
- `null` observation value → stored `missing`, never `0`.
- Specialist cannot read `private` journal entries via any route.
- Responses never include `password_hash` or internal fields.
